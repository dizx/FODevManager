# FO Dev Manager MCP stdio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Expose full existing FO Dev Manager workflow coverage through `fodev.exe mcp`.

**Architecture:** Official C# MCP SDK in the console host, typed tools calling shared application operations. Shared execution coordination protects MCP, CLI, and desktop mutations while preserving existing services and JSON contracts.

**Tech Stack:** .NET 10, C#, Microsoft.Extensions.Hosting, ModelContextProtocol SDK, NUnit, WinUI 3.

**Spec:** `docs/superpowers/specs/2026-09-14-mcp-stdio-design.md`

## Global Constraints

- Use the official C# ModelContextProtocol SDK
- Reserve stdout for MCP JSON-RPC traffic
- Preserve persisted profile JSON contracts
- Cover source, compiled, and compiled NuGet models, both repository-backed and standalone
- Use MessageLogger for application logging
- Use CRLF for touched text files, preserving explicitly configured LF
- Retain the user's existing FODevManager.WinUI/appsettings.json edit
- Do not commit, merge, or publish to a remote feed

## File structure

- `FoDevManager.Shared/Operations/`: execution lock, operation runner/results/history, shared headless workflow operations
- `FODevManager/Mcp/`: SDK host, typed tools grouped by domain, result adaptation and progress
- `FODevManager/Program.cs`: MCP dispatch, shared operation integration for CLI
- `FODevManager.WinUI/`: shared lock integration at operation boundaries
- `FODevManager.Tests/`: operation, workflow, protocol, and coverage tests
- `docs/mcp.md`: configuration, inventory, semantics, limitations

### Task 1: Shared operation execution infrastructure

**Files:** Create `FoDevManager.Shared/Operations/ApplicationOperationLock.cs`, `OperationRunner.cs`, `OperationResult.cs`, `SecretRedactor.cs`; create `FODevManager.Tests/OperationRunnerTests.cs`.

**Interfaces:** Produce `OperationRunner.RunAsync(string name, bool mutating, Func<CancellationToken, Task<object?>> action, CancellationToken cancellationToken = default, string? requestId = null, IProgress<string>? progress = null)` returning `Task<OperationResult>`; `GetStatus(string operationId)` returning `OperationResult?`; `ListOperations()` returning snapshots. OperationResult exposes operation ID, request ID, name, status, data, diagnostics, timestamps and partial-change indication. ApplicationOperationLock exposes a disposable non-blocking acquisition shared by application hosts. SecretRedactor sanitizes strings and structured data using AppConfig secrets and URL userinfo/query credentials.
